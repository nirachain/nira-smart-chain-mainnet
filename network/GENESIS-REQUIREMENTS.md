# Genesis requirements — approval required

Do not create or publish `genesis.json` until all items below are approved against the exact Nira client source revision.

- [ ] Chain ID selected and checked for conflicts
- [ ] P2P network ID selected
- [ ] Consensus model approved (retain/modify Satoshi Plus or another implementation)
- [ ] Validator election, staking/delegation, reward, slashing, and genesis validator set defined
- [ ] Any Bitcoin light-client/delegation dependencies and trust assumptions defined
- [ ] Genesis timestamp and extra data defined
- [ ] Native NIRA issuance, supply, decimals, allocations, vesting, and treasury rules approved
- [ ] EVM fork schedule and gas parameters matched to client support
- [ ] Predeploys/system contracts and their addresses/code hashes verified
- [ ] Client release and build reproducibility pinned
- [ ] Genesis generated by the pinned client tooling
- [ ] Genesis hash independently reproduced by at least two operators
- [ ] Testnet-to-mainnet migration and clean-datadir sync tested

The genesis JSON schema and consensus-specific fields must come from the pinned Nira client implementation. Do not copy an Ethereum, BNB Chain, or Core mainnet genesis and edit only its chain ID.
